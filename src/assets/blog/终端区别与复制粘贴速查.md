## 第一部分:几种终端的区别

> 先看第 0 节:终端 vs Shell 的概念澄清——搞清楚为什么这份文档里没有 PowerShell。

### 0. 先分清两个概念:终端 vs Shell(为什么没有 PowerShell?)

很多人把 PowerShell、cmd、bash 和"终端"混为一谈,其实它们是两个不同层面的东西:

| 概念 | 是什么 | 例子 |
|------|--------|------|
| 终端(终端模拟器) | 显示命令行界面的**窗口程序**,负责画界面、处理键盘鼠标 | conhost、Windows Terminal、VS Code 集成终端 |
| Shell(命令解释器) | **在窗口里接收并执行你命令的程序**,负责理解命令 | cmd、PowerShell、bash、zsh、fish |

比喻:终端是"电视机",Shell 是"电视台频道"。同一台电视(Windows Terminal)可以开多个标签页,一页播 PowerShell、一页播 Ubuntu(bash),互不影响。

- 所以文档标题是"终端区别",讲的是窗口程序;PowerShell 是 Shell 不是终端,因此没有单列
- PowerShell 在文档中出现的位置:默认 Profile 对比、`powershell.exe Get-Clipboard -Raw`、`powershell.exe -Command "..."`——都是把它当"Windows 侧的命令程序"在用

常用的 Shell:

| Shell | 说明 |
|-------|------|
| cmd(命令提示符) | 最老牌的 Windows Shell,DOS 时代传下来的,功能最弱 |
| PowerShell | 微软现代 Shell,比 cmd 强大得多(你这台机器上有) |
| bash | Linux 默认 Shell,WSL 里用的就是它,Hermes 也跑在里面 |
| zsh | macOS 默认 Shell,Linux 上也能装 |
| fish | 比较"友好"的 Shell,新手向,但生态小 |

常用的终端(和 Windows Terminal 同类的窗口程序):Cmder、ConEmu、Hyper、Alacritty、WezTerm、Tabby 等。这些大多是"折腾党"的选择,Windows 上微软官方推荐的就是 Windows Terminal,不用换。

### 1. 旧版控制台 (conhost / 传统命令提示符窗口)

- Windows 系统自带的最老控制台,单窗口、无标签页
- 通过"Win+R → cmd"、或直接双击 Ubuntu 快捷方式(未设置默认终端时)打开
- 特性:
  - QuickEdit 模式(默认开启):鼠标左键拖选 = 选中,右键 = 粘贴,选中后按 Enter = 复制
  - Ctrl+V 无效(粘贴靠右键或 Shift+Insert)
  - 中文/Unicode 显示容易出问题,无 GPU 渲染
- 适合:临时应急使用;长期使用不推荐

### 2. Windows Terminal (微软官方现代终端)

- 微软官方推荐终端,商店可装(包名 Microsoft.WindowsTerminal)
- 特性:
  - 多标签页、分屏、GPU 渲染、主题皮肤、Unicode 完美支持
  - 打开方式:开始菜单搜索 "Terminal" / "终端"
  - 配置保存在 settings.json(设置界面 Ctrl+, 可视化修改)
- 是 WSL 用户的首选终端

### 3. VS Code 集成终端

- 编辑器内嵌终端,跟随当前打开的项目目录
- 特性:
  - Ctrl+V 可以直接粘贴(和其他终端不同)
  - 复制:Ctrl+Shift+C
  - 跟随项目打开,适合边写代码边跑命令
- 右键行为可配置(默认有菜单)

### 4. 三者对比速查表(出厂默认键位)

| 终端 | 复制 | 粘贴 | 标签页 | 备注 |
|------|------|------|--------|------|
| 旧版 conhost | 选中+Enter 或右键 | 右键 / Shift+Insert | 无 | Ctrl+V 无效 |
| Windows Terminal | Ctrl+Shift+C | Ctrl+Shift+V / 右键 | 有 | 出厂默认 |
| VS Code 终端 | Ctrl+Shift+C | Ctrl+V / Ctrl+Shift+V | 有(编辑器内) | Ctrl+V 直接可用 |

### 5. 复制粘贴常见坑 (重点!)

- **右键 = 粘贴,不是复制**(三个终端都是)
- 剪贴板是空的时,怎么按粘贴都没反应——先确认剪贴板有没有内容
  - 验证命令:`powershell.exe Get-Clipboard -Raw`
- **Ctrl+C 在 bash 里永远是"中断信号",不是复制**
  - 即使在 Windows Terminal 设置里把 Ctrl+C 绑定了复制,在 WSL 的 bash 交互环境里也不会生效(终端必须把 Ctrl+C 发给 shell 用于停止命令)
  - 所以复制别按 Ctrl+C,用:鼠标选中(开启自动复制时)/ Ctrl+Shift+C
- 在 WSL 里"复制了却粘贴不出来",90% 是这个原因:按了 Ctrl+C 以为复制,实际是中断,剪贴板是空的

### 6. 如何判断自己当前在哪个终端

- 在 WSL 里执行 `echo $WT_SESSION`,有值 = Windows Terminal
- `echo $VSCODE_INJECTION`,有值 = VS Code 终端
- 都为空 = 旧版 conhost 或其他终端
- 看窗口标题/标签页:写 "Ubuntu" 且是多标签界面 = Windows Terminal
- 注意:Hermes 内部执行命令时环境变量会被剥离,从 Hermes 里检测不准;用 Windows 侧验证:
  - `tasklist.exe | grep -i WindowsTerminal`(有 WindowsTerminal.exe / OpenConsole.exe 就是 WT)

## 第二部分:你这台机器的自定义配置(相对出厂默认)

> 以下差异是实际对比 出厂默认(defaults.json) 与 你的配置文件(settings.json,最后修改于 2026-08-08 02:12)得出的,全部来自你的自定义设置,不是 Windows Terminal 自带行为。

### 1. Ctrl+V = 粘贴(新增)

- 出厂默认粘贴键是 **Ctrl+Shift+V**
- 你的 settings.json 显式绑定了 `ctrl+v → 粘贴`,所以你现在按 Ctrl+V 就能贴
- 这也是大多数人习惯的操作方式

### 2. Ctrl+C = 复制(新增,但 WSL 里实际不生效)

- 出厂默认**没有** Ctrl+C=复制 这个绑定(因为 Ctrl+C 是终端中断信号)
- 你的 settings.json 里绑了,但在 WSL 的 bash 交互环境里**永远不会触发**——按下去还是中断命令
- 实际效果:复制仍然靠 Ctrl+Shift+C 或"选中自动复制"

### 3. Alt+Shift+D = 分屏复制窗格(新增)

- 出厂默认的分屏键是 **Alt+Shift+-**(向下分屏)、**Alt+Shift+Plus**(向右分屏)
- 出厂默认 **Ctrl+Shift+D** = 复制标签页(这个你保留着)
- 你的配置里额外加了 Alt+Shift+D = 复制当前窗格(生成同内容的第二个窗格)

### 4. 选中自动复制(copyOnSelect)= 已开启

- 出厂默认:**关闭**(需要按 Ctrl+Shift+C 复制)
- 你的配置:**开启**——鼠标左键选中文字,松手即自动进剪贴板,不用按任何键
- 这是最省事的复制方式,配合 Ctrl+V 粘贴正好一套

### 5. 复制不带格式(copyFormatting = "none")

- 出厂默认:**带格式复制**(true,复制内容会带上字体/颜色等格式)
- 你的配置:**纯文本**(none)——从终端复制命令到编辑器/聊天框不会带乱七八糟的样式

### 6. 默认打开 Ubuntu(defaultProfile)

- 出厂默认:新开标签页默认是 **Windows PowerShell**
- 你的配置:默认是 **Ubuntu(WSL)**——打开终端直接进 Linux,不用每次手动选

### 7. 配置文件里自动检测到的 Profile

- 出厂默认只带:Windows PowerShell、命令提示符
- 你的列表里额外多了:Ubuntu(WSL)、Ubuntu(商店版)、Azure Cloud Shell——这是装完 WSL/商店应用后 Windows Terminal 自动检测出来的,不需要手动配

### 你的完整键位现状一览

| 功能 | 出厂默认 | 你的实际配置 | 生效情况 |
|------|----------|--------------|----------|
| 复制 | Ctrl+Shift+C | Ctrl+Shift+C(默认保留)+ 选中自动复制 + Ctrl+C(绑定但无效) | 推荐用选中自动复制 |
| 粘贴 | Ctrl+Shift+V | Ctrl+Shift+V(默认保留)+ **Ctrl+V**(新增) | Ctrl+V 可用 |
| 分屏 | Alt+Shift+- / Alt+Shift+Plus | 默认保留 + **Alt+Shift+D**(复制窗格) | 都可用 |
| 复制标签页 | Ctrl+Shift+D | 未改动 | 可用 |
| 选中自动复制 | 关 | **开** | 生效 |
| 复制格式 | 带格式 | **纯文本** | 生效 |
| 默认 Profile | PowerShell | **Ubuntu** | 生效 |

## 第三部分:WSL 基础命令(补充)

| 命令 | 说明 |
|------|------|
| `wslpath -w /home/xxx` | WSL 路径转 Windows 路径 |
| `wslpath -u "D:\\xxx"` | Windows 路径转 WSL 路径 |
| `ls /mnt/d/` | 访问 D 盘(挂载在 /mnt/d) |
| `explorer.exe .` | 用资源管理器打开当前目录 |
| `powershell.exe -Command "..."` | 在 WSL 里调用 Windows 命令 |
| `winget install --id <包名>` | Windows 侧安装软件(如 Microsoft.WindowsTerminal) |

### WSL 关机与再次进入(含 Hermes)

**为什么要手动关机**:任务管理器里 vmmem 进程常驻(那是 WSL 虚拟机的内存),想释放内存或彻底停掉 WSL 时才需要。平时不用管,关窗口≠关 WSL。

**关机流程(注意顺序)**:

1. 先退出 Hermes:在对话里输入 `/exit`
2. 再关 WSL:在 Windows 侧(PowerShell 或 CMD)执行 `wsl --shutdown`
   - 执行后任务管理器里的 vmmem 进程会在 1~2 秒内消失
   - 注意:直接 `wsl --shutdown` 会掐掉 WSL 里所有正在跑的东西(包括当前 Hermes 会话),所以必须先退出 Hermes 再关

**再次进入流程**:

1. 打开 Windows Terminal(开始菜单搜 "Terminal" / "终端")——你的默认标签页就是 Ubuntu,一打开 WSL 虚拟机就**自动开机**,不用手动启动
2. 等 1~5 秒,出现 `jsoncc@机器名:~$` 提示符再输入
3. 输入 `hermes -c` 回车 → 恢复上次的 Hermes 对话(之前聊的内容和记忆都在,对话存在 WSL 磁盘的数据库里,关机不会丢)
   - 想开全新对话:输入 `hermes` 回车

**一句话记住**:关机 = 先 `/exit` 再 `wsl --shutdown`;进入 = 打开 Terminal 等几秒再输 `hermes -c`

**两个坑**:

- 想"进入"的时候**别用** `wsl --shutdown`——那是关机命令
- 虚拟机开机那几秒提示符还没出来,别狂按键盘,等出现 `~$` 再输入

### bash 行编辑与"撤销"快捷键(输入命令时)

> 以下快捷键是 bash 自带的行编辑功能,与记事本里的 Ctrl+Z 撤销**不是一回事**。适用于还没按回车的时候。

| 想做的事 | 快捷键 | 说明 |
|---------|--------|------|
| 清空整行重新打 | Ctrl+U | 删掉光标左边的全部内容 |
| 彻底放弃当前行 | Ctrl+C | 回到干净的提示符(中断信号,不是复制!) |
| 跳到行首 | Ctrl+A | 光标移到最前面 |
| 跳到行尾 | Ctrl+E | 光标移到最后面 |
| 删光标前一个单词 | Ctrl+W | 只删一个词 |
| 删一个字符 | Backspace | 最基础 |

- **没有 Ctrl+Z 撤销打字**:终端里 Ctrl+Z 是"暂停当前程序",不是撤销
- 按了回车想重来:按 **↑** 调出上一条命令,修改后回车重跑(可连续按 ↑ 翻更早的)
- **命令执行后的后果无法撤销**(如 rm 删文件就是真删),重要的命令回车前先核对一遍
- Ctrl+L 是**清屏**,不是撤销,别混
